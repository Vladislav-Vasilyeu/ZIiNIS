# NeuralTextStego

Учебное приложение для исследования текстовой стеганографии. В графическом интерфейсе и CLI можно внедрять сообщения в текст, извлекать их и сравнивать методы. Поддерживаются TXT и DOCX, парольное шифрование и опциональный невидимый маркер.

## Методы

- `classic_synonyms` — замена слов по встроенному словарю.
- `classic_whitespace` — кодирование обычными и неразрывными пробелами.
- `neural_rank` — кодирование по рангу следующего токена.
- `neural_arithmetic` — упрощённое кодирование по корзинам накопленной вероятности; без переноса арифметического интервала между шагами.
- `neural_sampling` — кодирование выбором группы токенов.

Классические методы выполняются локально. Для нейросетевых методов нужна модель с поддержкой `logprobs` и `top_logprobs`. Для извлечения без маркера используйте те же модель, провайдер, промпт и параметры, что и при внедрении.

## Запуск

Требуется Python 3.10+ и Tk для графического интерфейса.

```powershell
cd NeuralTextStego_V3
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python main.py
```

На macOS и Linux используйте `python3 -m venv .venv`, `.venv/bin/python` и `cp .env.example .env`. Если `.env` уже существует, добавьте нужные параметры в существующий файл.

## Провайдеры

Провайдер и модель в верхней части окна применяются к генерации контейнера, нейросетевому внедрению, извлечению и экспериментам. Нажмите «Загрузить модели» и выберите модель в списке. ID модели также можно ввести вручную. Графический интерфейс запоминает выбор отдельно для каждого провайдера. В CLI укажите `--provider ollama`, `--provider tooken_club` или `--provider groq` и при необходимости `--model ID`. Начальный выбор провайдера задаёт `DEFAULT_LOGITS_PROVIDER`.

- **Ollama** использует локальный сервер. Укажите адрес в `OLLAMA_BASE_URL` и установленную модель в `OLLAMA_MODEL`.
- **Tooken Club** использует OpenAI-совместимый шлюз `https://tooken.club/v1`. Запишите ключ в `TOOKEN_CLUB_API_KEY` и ID модели в `TOOKEN_CLUB_MODEL`. Доступные ID возвращает `GET /v1/models` с заголовком `Authorization: Bearer <ключ>`. Приложение отправляет текстовые запросы на `POST /v1/chat/completions`. Ключ хранится в локальном `.env`.

Обычный чат Tooken Club подходит для генерации контейнера. Для нейросетевой стеганографии шлюз должен вернуть распределение в `choices[0].logprobs.content[0].top_logprobs`. Проверенные модели, включая `gpt-5.5` по умолчанию, отклонили этот параметр. Для нейросетевых методов используйте Ollama с поддержкой logprobs или укажите совместимую модель Tooken Club.


GroqCloud подключается через `GROQ_API_KEY` и `GROQ_MODEL` (по умолчанию `openai/gpt-oss-20b`). В GUI выберите **Groq**, нажмите «Загрузить модели» и выберите текстовую модель или введите её ID. Каталог API также содержит модели для аудио и модерации, назначение модели проверяйте в документации Groq. Провайдер использует `https://api.groq.com/openai/v1/models` и `/chat/completions`. Ключ передаётся в заголовке `Authorization: Bearer`.

Groq доступен для генерации контейнера. По [документации Groq](https://console.groq.com/docs/api-reference) параметры `logprobs` и `top_logprobs` пока не поддерживаются. Для трёх нейросетевых методов выберите провайдера с поддержкой распределения токенов. Классические методы работают с готовым контейнером локально.

Нейросетевая генерация Ollama использует непрерывный контекст с `OLLAMA_RAW_CONTINUATION=true` и префиксно-свободный набор текстовых токенов. При неуспешном извлечении программа также проверяет прежний режим контекста для старых стеготекстов.

## Пример CLI

Из каталога `NeuralTextStego_V3` с установленными зависимостями:

```bash
python main.py --cli embed --method classic_whitespace --cover data/sample_cover.txt --secret "hi" --out stego.txt
python main.py --cli extract --method classic_whitespace --stego stego.txt
python -m pytest -q
```

Приложение и тесты находятся в каталоге [NeuralTextStego_V3](NeuralTextStego_V3). Результаты экспериментов сохраняются в `experiments/results/`.


## Принцип работы и обработка ошибок

Полное [руководство по всем функциям](NeuralTextStego_V3/data/user_guide.txt) доступно также на вкладке «Справка» приложения. Оно объясняет пять методов, дополнительный канал маркера, шифрование, провайдеров, файлы, экспериментальные серии и ограничения.

До внедрения интерфейс показывает точную ёмкость классического контейнера и размер нагрузки: UTF-8, заголовок длины и служебные данные шифрования учитываются. Для «Секретное Сообщение» без пароля и маркера требуется 312 бит. Синонимический метод считает только слова из встроенного словаря; произвольный длинный текст может оказаться недостаточным. Внедрение в слишком маленький контейнер блокируется с подсказкой до запуска фоновой задачи.

Генерация через модель дополнительно проверяет вместимость классического контейнера. При нехватке текст дополняется локальными шаблонными предложениями, что явно отражается в статусе. Это гарантирует достаточную ёмкость для текущей нагрузки, но может ухудшать естественность текста. Ошибки облачных запросов не выдаются за успешную генерацию. При изменении секрета, пароля или метода ёмкость проверяется снова.

Одновременно выполняется одна операция. Отмена прерывает и ожидание сетевого запроса. Ошибка загрузки файла сохраняет прежнее содержимое поля. Секреты и пароли обрабатываются без удаления крайних пробелов. Передача результата на вкладку извлечения использует параметры последнего успешного внедрения; пароль вводится отдельно.

Маркер содержит полную полезную нагрузку в невидимых Unicode-символах. Его успешное чтение не доказывает, что основной метод вместил весь секрет. Для проверки основного алгоритма выключайте маркер. Стойкость к произвольному редактированию, естественность и статистическая незаметность автоматически не гарантируются.
