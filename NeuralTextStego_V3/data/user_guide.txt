КАК РАБОТАЕТ NEURALTEXTSTEGO

1. Что делает приложение

Программа прячет строку в другом тексте и извлекает её обратно. Исходный
безобидный текст называется контейнером, результат — стеготекстом.
Скрытие и шифрование — разные операции: пароль защищает содержимое,
а выбранный метод определяет способ записи данных в текст.

Общая последовательность:
секрет → UTF-8 → при наличии пароля шифрование → биты → внедрение.
Извлечение выполняет обратные преобразования. Например, английская A
занимает 1 байт (8 бит), русская Я — 2 байта (16 бит), многие эмодзи — 4 байта.
В режиме без маркера перед данными идут 16 бит длины полезной нагрузки
в байтах. Поэтому Hi занимает 16 + 2 × 8 = 32 бита.
«Секретное Сообщение» занимает 37 байт: 16 + 37 × 8 = 312 бит.
Лимит кадра — 65535 байт полезной нагрузки, включая результат шифрования.
Нейросетевое кодирование также ограничено числом генерируемых токенов.

2. Пять методов

ПРОБЕЛЫ. В подходящих позициях обычный пробел означает 0, неразрывный
пробел (NBSP, U+00A0) — 1. Одна позиция вмещает один бит. При новом
внедрении существующие NBSP сначала нормализуются, затем записываются биты.
Видимые слова сохраняются. Переформатирование текста и замена NBSP
обычным пробелом разрушают этот канал.

СИНОНИМЫ. Используется небольшой встроенный словарь, а не языковая модель.
У каждого распознаваемого слова есть стабильный набор из двух или четырёх
вариантов. Их индексы означают 0/1 или 00/01/10/11. Например, при четырёх
вариантах в одну позицию помещаются два бита. Большинство слов произвольного
текста не входят в словарь и ничего не кодируют. Длина текста в символах
не определяет его ёмкость. Замену можно восстановить без исходного контейнера,
поскольку кодовая книга одинакова при внедрении и извлечении. Словарные
замены могут ухудшать стиль и смысл; контекстная эквивалентность не доказана.

НЕЙРОСЕТЬ: РАНГ. Поле контейнера используется как исходный промпт.
Программа запрашивает вероятные следующие токены модели. Токен — фрагмент
текста: слово, часть слова, пробел или знак. При четырёх вариантах два бита
выбирают один из четырёх токенов. Выбранный фрагмент добавляется к контексту,
затем запрашивается следующее распределение. Результат содержит продолжение,
поэтому исходный промпт нужно сохранить отдельно и указать при извлечении.

НЕЙРОСЕТЬ: АРИФМЕТИЧЕСКОЕ КОДИРОВАНИЕ. В текущей реализации кандидаты
разделяются на корзины по накопленной вероятности, и биты выбирают корзину.
При пустых корзинах используется распределение по рангу. Это упрощённая
обратимая схема по вероятностям: полноценное арифметическое кодирование
с переносом интервала между шагами здесь не реализовано.

НЕЙРОСЕТЬ: СЭМПЛИРОВАНИЕ. Кандидаты делятся на группы по рангу. Биты
выбирают группу, из которой берётся первый подходящий кандидат. Несмотря
на название, это детерминированный выбор, а не случайная выборка токена.

При извлечении нейросетевых данных модель должна возвращать совместимое
распределение для того же контекста. Нужны тот же провайдер, модель,
промпт и параметры. Изменение модели или текста может нарушить извлечение.
В Ollama используется непрерывный raw-контекст. Пересекающиеся префиксы
токенов отфильтровываются, чтобы однозначно читать границы фрагментов.
Для старых стеготекстов предусмотрена повторная попытка прежнего режима.
Грамотность, незаметность и стойкость результата автоматически не доказаны.

3. Провайдер и модель

В верхней панели выбираются сервис и ID модели. «Загрузить модели»
получает каталог; ID также можно ввести вручную. Выбор сохраняется отдельно
для каждого провайдера. Список сервиса может содержать модели для аудио
или модерации, которые не подходят для генерации текста.

Ollama обращается к локальному серверу, в том числе Docker-контейнеру
с опубликованным портом 11434. Для нейросетевого кодирования нужна
совместимая модель, возвращающая logprobs/top_logprobs.

Tooken Club и Groq используют ключи из локального .env. Обычного текстового
ответа достаточно для подготовки контейнера, но для нейросетевых методов
требуются вероятности следующих токенов. Проверенный gpt-5.5 Tooken Club
их не возвращал; в интеграции Groq распределения недоступны. Ошибка
совместимости не исправляется увеличением контейнера или включением маркера.

Выбор провайдера не делает классические методы сетевыми: они изменяют
готовый текст локально. Сеть используется, если нажать генерацию контейнера.
Секрет и пароль не включаются в запрос генерации контейнера: модель получает
инструкции к тексту и желаемую длину. При нейросетевом кодировании провайдеру
передаётся растущий контекст с выбранными программой фрагментами.

4. Вкладка «Внедрение»

Выберите метод. Введите секрет и при необходимости пароль. Крайние пробелы
и переводы строк являются частью сообщения; пароль тоже учитывается точно.
Вставьте контейнер или загрузите TXT/DOCX. Для нейросетевого способа это
промпт; при пустом поле программа использует стандартное начало.

Под полями отображается требуемое число бит и фактическая ёмкость
классического контейнера. Если данных больше, чем помещается, внедрение
без маркера не запускается. Увеличьте контейнер, сократите секрет или
нажмите «Сгенерировать контейнер». Нельзя вместить 312 бит в 30 позиций
без изменения контейнера, метода или способа хранения.

Генерация запрашивает текст у выбранной модели, затем измеряет вместимость
классического метода. При нехватке программа просит модель дописать
текст и снова измеряет ёмкость (до трёх запросов). Если и этого мало,
добавляется локальный шаблонный текст с подходящими позициями. Источник результата явно указан в строке состояния.
Такой текст может быть повторяющимся; достаточная ёмкость не равна качеству
естественного языка. Для Ollama при недоступности модели разрешён локальный
запасной шаблон. Ошибки облачных сервисов показываются пользователю.

«Внедрить» создаёт результат. Прогресс показывает обработанные биты/токены,
после завершения доступны время и число шагов. «Отмена» прерывает текущую
задачу и ожидающий сетевой запрос; ресурсы клиента освобождаются. Одновременно
запускается одна операция. Кнопка «Отменить операцию» в нижней панели
доступна на любой вкладке. Результат предыдущей успешной операции сохраняется
при новой ошибке, поэтому проверяйте строку состояния.

«Копировать контейнер» копирует исходное поле. «Копировать» у результата
копирует стеготекст. «Сохранить» записывает его в TXT или новый DOCX.
«В извлечение» передаёт результат, метод, состояние маркера и исходный промпт
последнего успешного внедрения; восстанавливает выбранные тогда сервис
и модель. Пароль намеренно нужно ввести в поле извлечения отдельно.

5. Невидимый маркер

Это дополнительный канал: невидимые Unicode-символы в конце текста хранят
ПОЛНУЮ полезную нагрузку и контрольную сумму. При наличии пароля хранится
зашифрованная нагрузка, иначе — сам секрет в кодированном виде.

При включённом маркере извлечение сначала читает его. Поэтому сообщение
может восстановиться, даже если основной метод записал только часть битов.
Это нельзя считать успешным полным кодированием синонимами или токенами.
Статус сообщает о частичной записи. Маркер обнаруживается программно и
может быть удалён очисткой невидимых символов. Его контрольная сумма
обнаруживает повреждения, но не заменяет криптографическую аутентификацию.
Если маркер повреждён, программа сообщает об ошибке; он не игнорируется
незаметно. Если отсутствует, программа пробует основной канал.

Для проверки именно выбранного алгоритма выключите маркер и сравнивайте
восстановленное сообщение с оригиналом. Включайте маркер осознанно,
когда нужен дополнительный способ восстановления.

6. Пароль

Сначала Scrypt получает ключ из пароля со случайной солью. Затем AES-256-GCM
шифрует сообщение со случайным nonce и проверяет целостность при расшифровке.
Соль, nonce, шифротекст и тег упаковываются в Base64URL. Из-за служебных
данных и Base64 требуется больше позиций: исходный короткий секрет может
превратиться в значительно большую полезную нагрузку. Расчёт ёмкости это
учитывает. Пароль не хранится в настройках и не копируется автоматически.
Неверный пароль или повреждение вызывают ошибку, а не возвращают секрет.
Без пароля содержимое не зашифровано. Основной канал без маркера не имеет
собственной криптографической проверки подлинности.

7. Вкладка «Извлечение»

Загрузите или вставьте стеготекст, выберите исходный метод и режим маркера.
Если использовался пароль, введите его точно. Для нейросетевых методов
без маркера также укажите исходный промпт и совместимые сервис/модель.
Нажмите «Извлечь». Результат появляется в нижнем поле. Можно выделить
текст и скопировать обычным Ctrl+C. Ошибка извлечения не доказывает,
что секрет отсутствовал: причиной могут быть другой метод, пароль,
промпт, модель или изменение контейнера.

8. Вкладка «Эксперименты»

Укажите метод, сообщение, число повторов от 1 до 100 и режим маркера.
Серия использует локально созданный контейнер с фиксированным seed=42.
Для каждого повтора выполняются внедрение и извлечение, затем проверяется
точное совпадение сообщений. CSV в experiments/results содержит номер,
успех, биты, шаги, время и диагностическое сообщение. Кодировка UTF-8
с BOM и разделитель «;» подходят для открытия в Excel.

Серия показывает обратимость и длительность в конкретных условиях.
Она не измеряет автоматически незаметность, семантическую близость,
устойчивость к любым изменениям или статистическую безопасность.
Сравнивайте одинаковые сообщения и состояние маркера. Времена зависят
от модели, оборудования, прогрева сервера и сети.

9. Файлы и настройки

TXT читается в UTF-8, в том числе с BOM. Пробелы и переводы строк сохраняются.
DOCX читается как текст обычных абзацев. Сохранение создаёт новый документ;
таблицы, рисунки, колонтитулы и оформление исходного Word не переносятся.
Повреждённый или неподдерживаемый файл вызывает сообщение; прежний текст
в поле остаётся. Копирование через сторонние приложения может менять
пробелы и невидимые символы и тем самым повреждать скрытые данные.

Файл .env содержит ключи, адрес Ollama и модели по умолчанию.
После изменения .env перезапустите приложение. Не публикуйте ключи.
data/ui_state.json хранит метод, маркер, провайдера и выбранные модели.
Секреты и пароли в этот файл не записываются. Кнопка «Справка» открывает
это руководство. Приложение также предоставляет CLI через main.py --cli;
точные аргументы доступны в main.py --help.

10. Типовые ситуации

Недостаточно бит: увеличьте именно число кодирующих позиций или уменьшите
нагрузку. Пароль увеличивает её размер. Генерация проверяет ёмкость.
Нет соединения с Ollama: проверьте сервер/контейнер, опубликованный порт,
адрес OLLAMA_BASE_URL и наличие модели.
Нет API-ключа/HTTP 401: проверьте соответствующий ключ .env, перезапустите.
HTTP 402/403: проверьте баланс и разрешения в кабинете сервиса.
HTTP 429: проверьте квоту, подождите и повторите запрос.
Тайм-аут/HTTP 5xx: повторите позже или выберите другую доступную модель.
Нет top_logprobs: нужен совместимый провайдер и модель, обычного чата мало.
Неверный пароль/повреждение: проверьте пароль и сохранность исходного файла.
Не совпал токен: проверьте исходный промпт, модель, настройки и стеготекст.

Приложение обрабатывает проверенные сценарии ошибок, но совместимость
с произвольной моделью, любым файлом и любыми преобразованиями текста
не гарантируется. У ограничения должна быть понятная диагностика.


11. Подробные примеры нейросетевых методов

Модель предсказывает следующий токен по всему уже известному контексту.
Токен не обязан быть словом: он может быть частью слова или пробелом.
Программа не спрашивает модель, как спрятать секрет. Она получает список
кандидатов и сама выбирает следующий токен по очередным битам сообщения.

Перед внедрением Hi превращается в байты 0x48, 0x69, то есть
01001000 01101001. Перед ними записываются 16 бит числа 2 — длины в байтах:
0000000000000010 01001000 01101001.
Всего 32 бита. При двух битах на шаг нужно как минимум 16 шагов.
Если на шаге доступно только два или три кандидата, записывается один бит.
Если после фильтрации остаётся один кандидат, записывается ноль бит:
токен добавляется, контекст обновляется, кодирование продолжается.
Такие шаги всё равно расходуют лимит генерации.
Если Ollama случайно выбрала конец текста (EOS) и не прислала logprobs,
клиент проверяет ограниченную фиксированную последовательность seed.
Используются только настоящие вероятности модели. При неизменном
завершении программа сообщает, что нужен другой исходный контекст.

Для сравнения трёх методов возьмём ОДИН условный шаг. Это учебные числа,
не фактический ответ конкретной модели. Контекст: «За окном было».
Кандидаты по убыванию нормированной вероятности:
тепло 0.24, холодно 0.20, тихо 0.16, темно 0.14,
светло 0.10, ветрено 0.07, пасмурно 0.05, солнечно 0.04.
Пробел перед словом считаем частью токена. Очередная пара битов — 11.

РАНГ. Из восьми кандидатов при chunk_bits=2 используются первые четыре:
00 → тепло; 01 → холодно; 10 → тихо; 11 → темно.
Программа добавит « темно». При извлечении та же модель получает тот же
контекст, программа видит « темно», находит индекс 3 и восстанавливает 11.
На следующем шаге контекст уже «За окном было темно». Список кандидатов
будет новым; прежнее соответствие нельзя применять ко всему предложению.

ГРУППЫ ПО РАНГУ (название в интерфейсе — сэмплирование).
Все восемь кандидатов делятся на четыре последовательные группы:
00 → тепло, холодно; 01 → тихо, темно;
10 → светло, ветрено; 11 → пасмурно, солнечно.
Для 11 берётся первый кандидат группы: « пасмурно».
При извлечении « пасмурно» относится к группе 11.
По сравнению с ранговым методом кодирование использует более широкий
набор кандидатов. Выбор первого кандидата детерминирован; случайной
выборки внутри группы в текущем приложении нет.

ГРУППЫ ПО ВЕРОЯТНОСТИ (название — арифметическое кодирование).
Вероятности сначала нормируются с учётом temperature:
p_i = exp(logprob_i / T) / сумма exp(logprob_j / T).
Числа выше уже считаем результатом этой нормировки.
На числовой оси [0,1) кандидаты занимают последовательные интервалы:
тепло [0,.24), холодно [.24,.44), тихо [.44,.60), темно [.60,.74),
светло [.74,.84), ветрено [.84,.91), пасмурно [.91,.96),
солнечно [.96,1).
Четыре битовые группы соответствуют четвертям оси:
00: [0,.25), 01: [.25,.50), 10: [.50,.75), 11: [.75,1).
Кандидат относится к группе по СЕРЕДИНЕ своего интервала:
тепло .12 → 00; холодно .34 → 01; тихо .52 → 10; темно .67 → 10;
светло .79 → 11; ветрено .875 → 11; пасмурно .935 → 11;
солнечно .98 → 11.
Для 11 выбирается первый кандидат этой группы: « светло».
При извлечении та же середина .79 восстанавливает группу 11.
Если распределение получилось настолько неравномерным, что одна из
групп пуста, используется запасное разбиение по рангу, чтобы для каждой
комбинации битов существовал вариант.

Таким образом, на одном условном шаге для одних и тех же битов 11:
ранг выбирает «темно», группы по рангу — «пасмурно»,
группы по вероятности — «светло».

Это не полноценный классический арифметический кодер: интервалы не
переносятся и не сужаются между шагами. Каждый шаг заново делит кандидатов
на группы и обычно записывает до двух битов. Полноценный арифметический
алгоритм потребовал бы иной реализации и отдельной проверки совместимости.

12. Зачем исходный промпт при извлечении

Пусть внедрение начиналось с «За окном было», а результат начинается
с « темно». Чтобы понять, какие биты означает « темно», надо восстановить
исходный список кандидатов. Он зависел от «За окном было».
При другом контексте то же слово может иметь иной ранг или вообще
не попасть в список. Поэтому сам стеготекст без исходного контекста
не всегда достаточен для извлечения.

Промпт — не секретный пароль и не инструкция «расшифруй текст».
Это точная исходная строка до первого сгенерированного токена.
На втором шаге к ней добавляется первый наблюдаемый токен и так далее.
Необходимо совпадение пробелов, переводов строк, модели и параметров.
Промпт может быть согласован заранее между отправителем и получателем.
Классические методы его не используют. Если полный секрет прочитан
из невидимого маркера, модель и промпт для этого чтения не нужны.

13. Можно ли получать синонимы от нейросети

Да, модель может предложить контекстные замены вместо заранее написанного
словаря. Но для извлечения нужны одинаковые варианты В ОДИНАКОВОМ ПОРЯДКЕ.
Например: [быстрый, скорый, оперативный, стремительный] означает
[00,01,10,11]. Если при извлечении модель поменяет порядок, биты изменятся.
Запрос с другим исходным словом или уже изменённым контекстом также
может дать другую группу. Даже temperature=0 не является гарантией
совпадения между версиями модели и разными сервисами.

Надёжный вариант — один раз получить кодовую книгу от модели, проверить
варианты и сохранить её как параметры проекта для обеих сторон.
Это позволяет отказаться от ручного встроенного словаря, но не от
общего правила соответствия между словами и битами. Можно передавать
кодовую книгу отдельным файлом. Это новая функция; текущий синонимический
метод пока использует прежний встроенный словарь.

14. Шифрование подробно

Для Hi с паролем сначала создаётся случайная соль 16 байт. Scrypt получает
из пароля и соли ключ 32 байта (256 бит); параметры N=16384, r=8, p=1.
Соль не является паролем и хранится рядом с шифротекстом. Её назначение —
получать разные ключи при повторном использовании одного пароля.

Затем создаётся случайный nonce 12 байт. AES-GCM шифрует два байта Hi
и добавляет 16-байтовый тег целостности. Результат упаковывается:
соль(16) + nonce(12) + шифротекст(2) + тег(16) = 46 байт.
Base64URL превращает их в 64 ASCII-символа. Это кодировка, не ещё один шифр.
После 16-битного заголовка для внедрения нужно 64*8+16 = 528 бит.
Без пароля Hi требует 32 бита. Для фразы «Секретное Сообщение»:
37 байт + 44 служебных = 81 байт → 108 байт Base64URL → 880 бит с заголовком.

При извлечении выполняются обратные действия: Base64URL декодируется,
соль и nonce отделяются, тот же Scrypt получает ключ из введённого пароля,
AES-GCM проверяет тег и возвращает исходные байты. При ошибке пароля или
повреждении проверки не проходят. Пароль не записывается в контейнер.
Одинаковые секрет и пароль обычно дают разные шифротексты из-за новых
случайных соли и nonce. Пароль не отправляется языковой модели.


15. Контроль успешного нейросетевого внедрения

Без маркера программа сама выполняет обратное извлечение сразу после
создания стеготекста и сравнивает сообщение точно. Несовпадение не выдаётся
за успешное внедрение. Такая проверка требует дополнительных запросов
к модели и увеличивает длительность операции. Она обнаруживает текущий
сбой, но не гарантирует совместимость после обновления модели/сервера
или изменения аппаратного режима. Один seed не устраняет все возможные
источники численной недетерминированности. Для работы без исходного
общего словаря/контекста нужна отдельная схема переносимых параметров.
